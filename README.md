# Python-Fire
[![CI Pipeline](https://github.com/rowshanattar/Python-Fire/actions/workflows/main.yml/badge.svg)](https://github.com/rowshanattar/Python-Fire/actions/workflows/main.yml)

A learning project that goes from Python basics to building **command-line tools (CLIs)**.
It starts with notebooks on statements and functions, sets up a tested and linted project
with a CI pipeline, builds a CLI that asks Claude (Anthropic's LLM) for a short summary of a
topic using **Click**, turns the same function into a CLI with **Python Fire**, serves it as
a web API with **FastAPI**, and finally packages the API in a **Docker** container.

| `fire-cli.py` | **The Fire CLI.** One line, `fire.Fire(claude)`, turns the `mylib` function into a CLI. |
| `main.py` | **The web API.** A FastAPI app with a `POST /summarize` endpoint, run with Uvicorn. |
| `invoke.sh` | A `curl` command that sends a sample request to the running API. |
| `Dockerfile` | Builds a container image that runs the API with Uvicorn on port 8000. |
| `.dockerignore` | Keeps secrets (`.env`), Git data, caches and notebooks out of the Docker image. |
| `test_hello.py`, `test_LLMbot.py`, `test_main.py` | Pytest tests for `hello.py`, the Claude logic and the API. |
| `Makefile` | Shortcuts: `make install`, `make test`, `make format`, `make lint`. |
| `.github/workflows/main.yml` | GitHub Actions CI: install, format, lint and test on every push to `main`. |
| `requirements.txt` | Project dependencies. |

The main idea is to **keep the logic and the interface separate**. `mylib/LLMbot.py` holds
the logic in a plain function. `LLMbot.py`, `fire-cli.py` and `main.py` each put a different
interface on top of it. Tests target the logic, so the same function can be used by Click,
by Fire, by FastAPI, or from any other Python code.

# Pass everything as options

`--help` prints:

Usage: LLMbot.py [OPTIONS]

Options:
  --topic TEXT         The topic to summarize
  --sentences INTEGER  The number of sentences for the summary

from mylib.LLMbot import claude

## What is a CLI, and why build one?

A **CLI (command-line interface)** is a program you run from the terminal with arguments,
for example `git commit -m "msg"` or `pip install requests`. Turning a script into a CLI
gives you:

- **Reuse without editing code.** Change inputs with flags instead of editing variables in the file.
- **Automation.** CLIs work in shell scripts, cron jobs, Makefiles and CI pipelines.
- **Self-documentation.** `--help` tells users what the tool does and what it accepts.
- **Composability.** Output can be piped into other tools (`python LLMbot.py --topic X > out.txt`).

Python has three common ways to build one:

| Tool | Style | Effort |
| --- | --- | --- |
| `argparse` (standard library) | You build a parser object by hand | Most code |
| **Click** | You add decorators to functions | Medium, lots of control |
| **Python Fire** | You pass any Python object to `fire.Fire()` | Almost none |

## Click explained

[Click](https://click.palletsprojects.com/) ("Command Line Interface Creation Kit") builds
CLIs with **decorators**. You write a normal function and describe its arguments in
decorators above it.

This is the core of `LLMbot.py`:

```python
import click

@click.command()                                   # 1. make this function a CLI command
@click.option('--topic', prompt='Enter a topic',   # 2. a --topic option; ask for it if missing
              help='The topic to summarize')
@click.option('--sentences', default=2,            # 3. a --sentences option with a default
              help='The number of sentences for the summary')
def claude(topic, sentences):
    """Generate a summary about the given topic..."""  # 4. docstring becomes the --help text
    ...
    click.echo(summary)                            # 5. print safely across platforms

if __name__ == '__main__':
    claude()                                       # 6. Click reads the args from sys.argv
```

### Key Click concepts

- **`@click.command()`** turns a function into a command-line command.
- **`@click.option('--name')`** adds an optional flag such as `--name value`. Useful settings:
  - `default=...` sets a value used when the flag isn't given. Click also infers the type from it (`default=2` makes it an `INTEGER`).
  - `type=int / float / click.Choice([...]) / click.Path()` converts and validates input.
  - `prompt='...'` asks the user interactively if the flag is missing.
  - `help='...'` is the text shown in `--help`.
  - `is_flag=True` makes a boolean switch such as `--verbose`.
- **`@click.argument('name')`** adds a required positional argument (`mycli.py value`).
- **`@click.group()`** groups several commands under one tool, like `git commit` and `git push`:

  ```python
  @click.group()
  def cli():
      pass

  @cli.command()
  def summarize(): ...

  @cli.command()
  def translate(): ...
  ```

- **`click.echo()`** is a `print()` that works across terminals and encodings.
- **Testing:** `click.testing.CliRunner` runs a command in tests and captures its output:

  ```python
  from click.testing import CliRunner
  from LLMbot import claude

  result = CliRunner().invoke(claude, ["--topic", "Python", "--sentences", "1"])
  assert result.exit_code == 0
  ```

> **Note:** A Click command reads its arguments from the command line, so call it as
> `claude()`, not `claude("Python", 2)`. To call the logic directly with values, use
> `mylib.LLMbot.claude(topic, sentences)`. That's why the logic lives in `mylib`.

## Python Fire explained

[Python Fire](https://github.com/google/python-fire) is a Google library that
**generates a CLI from any Python object**: a function, a class, an instance, a module, a
dict or a list. You don't need decorators or to declare options. Fire reads the object's
signature and builds the interface for you.

```bash
pip install fire
```

### A function becomes a command

```python
# fire-cli.py
import fire
from mylib.LLMbot import claude

fire.Fire(claude)
```

> **Pass the function, don't call it.** `fire.Fire(claude("Python", 2))` would run the
> function first and hand Fire the returned *string*. Fire would then offer string methods
> such as `upper` and `split` as commands, and `--topic` would fail with
> `Could not consume arg`.

```bash
python fire-cli.py Python 2                          # positional arguments
python fire-cli.py --topic=Python --sentences=2      # named arguments
python fire-cli.py --topic "Machine Learning"        # error: sentences has no default
python fire-cli.py --help                            # help generated from signature and docstring
```

Nothing in `mylib/LLMbot.py` had to change. The same function that the tests import is now
a CLI. This is the benefit of keeping the logic separate from the interface.

### A class becomes a tool with subcommands

Each method becomes a subcommand, and `__init__` arguments become global flags:

```python
import fire
from mylib.LLMbot import claude

class Bot:
    """A small toolbox around Claude."""

    def __init__(self, sentences=2):
        self.sentences = sentences

    def summarize(self, topic):
        """Summarize a topic."""
        return claude(topic, self.sentences)

    def compare(self, a, b):
        """Summarize two topics one after another."""
        return {a: claude(a, self.sentences), b: claude(b, self.sentences)}

if __name__ == "__main__":
    fire.Fire(Bot)
```

```bash
python fire-cli.py summarize Python
python fire-cli.py summarize Python --sentences=4
python fire-cli.py compare Python Java
python fire-cli.py --help
```

### Other things Fire can do

- **`fire.Fire()` with no argument** exposes everything in the current module: every function and class becomes a command.
- **Dicts** become command menus: `fire.Fire({"add": add, "summarize": claude})` gives `python cli.py add 2 3`.
- **Chaining:** if a command returns an object, you can call its methods in the same line, for example `python cli.py summarize Python upper` runs `.upper()` on the result.
- **Types are parsed automatically:** `2` becomes an `int`, `2.5` a `float`, `[1,2]` a `list`, `True` a `bool`. Wrap a value in quotes to force a string: `'"2"'`.
- **Interactive mode:** `python cli.py -- --interactive` opens an IPython shell with your object loaded. (IPython is already in `requirements.txt`.)
- **Debugging:** `python cli.py summarize Python -- --trace` shows the steps Fire took.

Even `hello.py` can become a CLI in one line:

```python
import fire
from hello import add

fire.Fire(add)        # python cli.py 2 3  ->  5
```

## Click vs. Fire

| | **Click** | **Python Fire** |
| --- | --- | --- |
| How you define the CLI | Decorators on each function | `fire.Fire(obj)`, one line |
| Changes to your code | Function is tied to Click | None: works on existing functions and classes |
| Help text | Written explicitly (`help=`) | Taken from signatures and docstrings |
| Validation and types | Strong (`type=`, `Choice`, `Path`, ...) | Guesses from the input text |
| Prompts, flags, env vars | Built in | Not built in |
| Best for | Polished CLIs for end users | Quick CLIs, internal tools, exploring code |

This repo builds both:
**Click** for a carefully designed user-facing command, and **Fire** as the fastest way to
put a CLI on the Python objects that already exist.

## API endpoint with FastAPI and Uvicorn

A CLI is for people at a terminal. An **API** lets other programs, such as a website, a
mobile app or another service, use the same logic over HTTP. `main.py` puts the same
`mylib.LLMbot.claude` function behind a web endpoint:

- **[FastAPI](https://fastapi.tiangolo.com/)** is the web framework. It defines the
  endpoints, validates input and generates interactive documentation.
- **[Pydantic](https://docs.pydantic.dev/)** describes the shape of the JSON request, so
  invalid input is rejected automatically with a clear error.
- **[Uvicorn](https://www.uvicorn.org/)** is the server that runs the FastAPI app.

### Endpoints

| Method | Path | Input | Returns |
| --- | --- | --- | --- |
| `GET` | `/` | Nothing | A welcome message |
| `POST` | `/summarize` | JSON body `{"topic": str, "sentences": int}` | `{"summary": "..."}` |
| `GET` | `/docs` | Nothing | Interactive Swagger UI, generated by FastAPI |
| `GET` | `/redoc` | Nothing | Alternative API documentation |

The request body is validated by the `SummarizeRequest` model:

```python
class SummarizeRequest(BaseModel):
    topic: str = Field(min_length=1)   # must not be empty
    sentences: int = Field(gt=0)       # must be 1 or more
```

**GET or POST?** Use `GET` to read something with small inputs that can go in the URL. Use
`POST` to send data in the request body, especially when it's large, nested or sensitive, or
when the call triggers an action. `/summarize` uses `POST` because it takes a JSON body and
each call costs an API request to Claude.

### Run the server

```bash
python main.py
# or, with auto-reload while you edit the code:
uvicorn main:app --reload
```

Uvicorn prints `Uvicorn running on http://0.0.0.0:8000`. `0.0.0.0` means "listen on all
network interfaces"; it isn't an address to open in the browser. Use
**http://127.0.0.1:8000** or **http://localhost:8000** instead. Keep the terminal open: the
API only works while the server is running.

### Try it

**In the browser:** open [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs), expand
`POST /summarize`, click **Try it out**, edit the JSON and click **Execute**.

**With curl** (or run `sh invoke.sh`, which sends the same request):

```bash
curl -X POST 'http://127.0.0.1:8000/summarize' \
  -H 'Content-Type: application/json' \
  -d '{"topic": "Google", "sentences": 1}'
```

Response:

```json
{
  "summary": "Google, founded in 1998 by Larry Page and Sergey Brin and now a subsidiary of Alphabet Inc., is a global technology company best known for its search engine, as well as products like Android, Chrome, YouTube, Gmail, and Google Cloud, and it generates most of its revenue from online advertising."
}
```

**From Python** (needs `pip install requests`):

```python
import requests

response = requests.post(
    "http://127.0.0.1:8000/summarize",
    json={"topic": "Google", "sentences": 1},
)
print(response.json()["summary"])
```

### Errors

| Status | When |
| --- | --- |
| `200 OK` | The summary was generated. |
| `422 Unprocessable Entity` | The JSON doesn't match `SummarizeRequest`: a missing field, a wrong type such as `"sentences": "two"`, an empty `topic`, or `sentences` of 0 or less. Pydantic produces this automatically, and `detail` explains which field failed. |
| `500 Internal Server Error` | The call to Claude failed, for example because `ANTHROPIC_API_KEY` is missing or invalid. The response is plain text; the full error appears in the server's terminal output. |

## Running the API in Docker

### Build and run

```bash
# Build the image and name it python-fire
docker build -t python-fire .

# Run it, passing the API key from .env and mapping port 8000 to your machine
docker run --rm -p 8000:8000 --env-file .env python-fire
```

Then use the API exactly as before: open http://127.0.0.1:8000/docs or run `sh invoke.sh`.
Inside the container Uvicorn must listen on `0.0.0.0`, otherwise requests from outside the
container can't reach it. Press `Ctrl+C` to stop the container.

### Run the tests in the container

The test files are included in the image, so you can run them there too:

```bash
docker run --rm --env-file .env python-fire python -m pytest -vv test_*.py
```

(The `python:3.11-slim` image doesn't include `make`, so call pytest directly.)

## Testing, formatting, linting and CI

```bash
make test      # pytest -vv test_*.py
make format    # black *.py
make lint      # pylint --disable=R,C *.py
```

- `test_hello.py` checks that `add(2, 3) == 5`.
- `test_LLMbot.py` calls the real Claude API and checks that the summary is a non-empty
  string that mentions the topic.
- `test_main.py` uses FastAPI's `TestClient` to call `POST /summarize` without starting a
  server. It checks that a valid request returns `200`, and that a missing `topic` or a
  negative `sentences` returns `422`.

`test_LLMbot.py` and `test_main.py` call the real Claude API, so **they need
`ANTHROPIC_API_KEY`** in your environment or `.env`.

**CI:** `.github/workflows/main.yml` runs `install → format → lint → test` on every push to
`main`, using Python 3.11 (the same version as the Docker image). The API key comes from the repository secret `ANTHROPIC_API_KEY`
(*Settings → Secrets and variables → Actions*). The badge at the top shows the latest result.
